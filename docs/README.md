# Documentation

The Design Prototyping Kit is a template for prototyping iP: Intelligence Platform screens with the components and design tokens iP uses, on mock data, with Claude Code doing most of the building.

## Guides

Start here if you're designing or building a prototype.

| Guide | What it covers |
|---|---|
| [Getting started](getting-started.md) | Setting up your copy, running the prototype and Storybook, branches and pull requests |
| [Using Claude Code](using-claude-code.md) | How Claude knows the rules, good prompts, the build loop, what Claude won't do |
| [Components and Storybook](components-and-storybook.md) | Browsing the components, the three tiers, design tokens |
| [Understanding the data](understanding-the-data.md) | The mock data files and how to change them (generated by `npm run docs:data`) |
| [Why was my work rejected?](why-was-my-work-rejected.md) | The automatic checks, what each error means and how to fix it |

## Keeping docs up to date

- Docs live here, in the repo, so they change in the same pull request as the code they describe.
- `understanding-the-data.md` is generated: change `scripts/generate-data-docs.js`, not the page. CI regenerates it on every push to `main`.
- When a rule changes, update [the design system reference](reference/design-system.md) first; other docs link to it rather than repeating it.
